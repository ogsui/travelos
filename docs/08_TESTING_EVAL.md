# 08 Testing, Evaluation & Rollout

## Test pyramid
`tests/unit` (pure logic, property tests) · `tests/integration` (DB, Redis, adapters vs mocks) · `tests/contract` (every adapter interface; runs against mock and, when available, sandbox) · `tests/eval` (LLM quality + adversarial) · `tests/e2e` (inquiry -> invoice on synthetic data, Playwright for the dashboard).

Database integration tests start a bundled PostgreSQL 16 through the dev-only `pgserver` dependency, so no Docker or local server is needed. They run real Alembic migrations (upgrade, seeded downgrade, re-upgrade), CHECK constraints, partial indexes, the append-only trigger and encryption at rest; `make test-integration` selects them with `-m integration`.

Auth tests (task 003) clone a migrated template database per test. They cover Argon2 hashing, RFC 6238 TOTP vectors, the role/permission matrix, session expiry/revocation, audit redaction and diffs, flag cache TTL/invalidation, and the HTTP surface: every route has an allowed and a denied role test (or an explicit public test), plus a registry test that fails when a new route is added without a matching access test. Login, MFA, permission denials and flag writes are asserted against real `audit_log` rows.

Workflow tests (task 004) are table-driven from a hand-written copy of the documented state machines, so a drifted definition fails. Every `(state, trigger)` pair is exercised, including wildcard inquiry exits and terminal states; guards are tested with and without their context flag. A Hypothesis test fires arbitrary triggers and asserts no undeclared target is ever produced. Outbox tests cover success, duplicate delivery (handler runs once), retry timing with a `ManualClock`, dead-letter human tasks, batch limits, chained events and the worker entry point. Timer tests cover fake-clock firing, fire-once, re-arm, cancel and the timer defaults. `tests/unit/test_worker.py` checks Celery registration and the beat schedule without a broker.

Approval tests (task 005) are split the same way. `tests/unit/test_approval_matrix.py` pins the catalogue against `docs/05_APPROVAL_MATRIX.md`: every LOCKED action is frozen, the locked set and owner-only set are explicit, A0 denies, A1 needs approval, A2 carries review-after, A3 is automatic, stored levels clamp to the ceiling and unknown actions fail closed. It also covers four-eyes by catalogue flag, policy flag and monetary threshold. `tests/integration/test_approval.py` exercises the full lifecycle against PostgreSQL: submit creates a pending request with two timers, a human task, an outbox event and a metric; approve/edit/reject write before/after audit rows; the requester cannot self-approve; four-eyes requires two distinct reviewers; owner-only actions reject other roles; escalation and expiry fire from timers, create owner tasks and are idempotent on redelivery; the policy seed inserts missing rows, repairs tampered rows and preserves safer owner changes; and demotion triggers on incidents or a sub-85% approval rate, once per metric window, never for LOCKED actions. `tests/integration/test_approvals_api.py` covers the API surface (`/approvals` submit/list/get/decide and `/autonomy/policies` read/update), and `tests/integration/test_route_access.py` enforces an access test for every new route.

LLM gateway tests (task 006) are layered. Unit tests cover reversible PII placeholders, injection sanitising and delimiter escaping, the prompt registry/front matter/rendering contract, the JSON Schema subset, provider HTTP error mapping against `httpx.MockTransport` (no network), integer-paise cost arithmetic, cache TTL/LRU behaviour, circuit-breaker transitions and factory wiring. `tests/integration/test_llm_gateway.py` runs the real gateway and `llm_calls` table: customer data to a `synthetic_only` provider is refused before any call, one schema failure is repaired and both attempts are costed, two schema failures raise and create a human task, auth failure falls back, total failure escalates, the daily budget blocks before a provider is used, a zero budget routes only to an explicitly free provider and blocks unpriced ones, the budget day resets at Indian midnight rather than UTC, cache hits avoid a second call, PII is absent from the provider request and stored rows, and both ORM and raw-SQL mutation of `llm_calls` are blocked. `tests/integration/test_llm_retention.py` proves the 90-day purge deletes only expired rows, can be scoped to a tenant, writes the audit row and leaves the append-only guard active for any later delete. `tests/eval/test_llm_injection.py` is a pure (no database) eval over `data/eval/llm_injection.jsonl`: every compromised output fails the schema or allow-list, control tokens and delimiter escape attempts are neutralised, and the request type has no tool field. A database-backed version of the same fixtures lives in the integration test.

## Synthetic dataset (task 007) — everything obviously fake

(`data/schemas/` holds the JSON Schemas, `data/synthetic/manifest.json` the
seed, counts and SHA-256 per file). Run `make seed` to regenerate; `SYNTHETIC_SEED`
defaults to `20261025`. The same seed produces byte-identical files. `make seed`
also loads the CRM rows (customers, contacts, consents, suppression list,
travellers) idempotently; later tasks consume the remaining JSONL files as their
tables land.

## Inquiry parser eval (task 010d)
The hand-checked gold set is `data/eval/inquiry_gold.jsonl`: 32 synthetic
messages, two per synthetic category, with a full gold requirement, the verbatim
evidence quote(s) for every asserted field, and notes on corrections and
ambiguity. Gold keeps names and cities exactly as the customer wrote them
(misspellings included), converts budgets to integer paise and marks only what
the message states. `data/eval/inquiry_injection.jsonl` holds compromised parser
payloads that must be rejected (extra action key, invalid trip type, fabricated
quote, silent assumption).

Two modes, and the result file always says which one produced the number:

```sh
python -m travelos.inquiry.eval --mode fake        # CI plumbing, no model
python -m travelos.inquiry.eval --mode provider    # owner-configured model + database
```

`fake` echoes the gold answer back through the real schema, evidence and scoring
code. It proves the harness works but is **not** an accuracy measurement: its
result records `gate.status = "not_measured"` and `passed = null`. `provider`
calls the real gateway, writes `llm_calls`/audit rows, and is the only mode that
can pass or fail the gate. It refuses to run when the configured provider chain
still contains `fake`. The result is one JSON file per prompt version:
`data/eval/results/inquiry_parser_v<version>.json`; a fake run never overwrites a
provider result. A prompt version with no result file is not a pass.

The file reports required-field accuracy (per trip-type required field, including
correctly-absent fields), extraction accuracy over every asserted gold field,
required-field precision/recall, missing-info agreement with `inquiry.rules`,
confidence calibration (Brier score plus 0.0-0.5/0.5-0.7/0.7-0.9/0.9-1.0 buckets),
silent-assumption cases and injection containment, per field and in total.
Provider mode fails the gate below 95% required-field accuracy, on any silent
assumption, parse failure or injection that is not contained.

CI runs the database-free tests in `tests/eval/test_inquiry_parser_eval.py`
(fixture traceability, category coverage, fake-mode plumbing, scorer miss/extra
reporting, injection containment, a committed result per prompt version, and the
no-downgrade rule). `tests/integration/test_inquiry_eval_provider.py` drives
`run_provider_eval` through the real gateway and database with a scripted
provider to prove provider-mode plumbing and `llm_calls` provenance; it is not a
quality measurement.

Current committed result: `data/eval/results/inquiry_parser_v1.json` is a **fake
mode** run (`gate.status = "not_measured"`). A real baseline is blocked until the
owner supplies a non-fake provider, model and budget (see `docs/BACKLOG.md`).

## Competitor price comparability (task 014a1)
`tests/unit/test_market_comparability.py` (44 tests, two hypothesis properties)
pins the pure `market` rules that decide whether a competitor price may influence
the price ceiling:

- an identical observation scores 100/100 and is comparable; route matching
  ignores case, spacing, arrow, en dash and "to";
- a reversed route, a different product type, a foreign currency, a stale or
  future-dated fetch, a blocked/unavailable portal result, a two-day date shift,
  a changed stay length, a one-way/return mismatch, a different party, fare class
  or refundability, or a baggage allowance more than one bag apart are each
  refused with their own reason;
- a one-day shift with the same length scores 88, one extra checked bag 95, an
  unstated fare class or refundability 90, and more than 20 points of unknown
  detail is `insufficient_detail`;
- the threshold, maximum age and one-way handling are policy/product values and
  are exercised by a lower-threshold, a one-hour-age and a one-way case;
- the reference is the exact integer median of comparable prices, an outlier
  (three MADs, 10% relative floor) never moves it, ordering is by price then
  site, and an empty or all-blocked input returns no reference plus
  `no_trusted_prices` without raising. That is the MKT-3 behaviour: competitor
  data missing never blocks quoting.

The defaults (threshold 80, 20 points of unknown detail, one-day tolerance,
24-hour age, three-MAD outlier rule) are engineering placeholders for owner
confirmation in `docs/BACKLOG.md`. That slice contains no persistence, adapter,
portal automation or currency conversion.

## Competitor price adapters (task 014a2a)
`tests/unit/test_market_adapters.py` (18 tests) pins the offline adapter
contract:

- `ManualEntryAdapter` returns exactly the entries staff recorded, refuses an
  entry that names another site, refuses a blocked or unavailable observation,
  and reports `unavailable` with a reason when nothing was recorded;
- `LicensedDataAdapter` is a stub that always reports `unavailable` and never
  raises, so no invented price can enter a quote before an owner-supplied
  provider contract exists;
- `fetch_competitor_prices` runs adapters in order, turns an exception into
  `unavailable` whose detail carries only the exception type name (the test
  asserts a token in the message does not leak), and keeps another site's prices
  when one adapter fails; an empty adapter list returns an empty tuple;
- `competitor_observations` flattens successful fetches in adapter order, and a
  manual price set still produces a reference through the 014a1 comparator when a
  sibling adapter fails;
- `CompetitorFetch` invariants: a blank site, a naive fetch time, an `ok` fetch
  with no prices and a failed fetch carrying prices are rejected; fetch times are
  normalised to UTC.

The adapters do not touch the network, a browser, the database or an LLM. Portal
automation and the operator resume flow are 014b; the collection loop, per-site
flags and cache/throttle are 014a2b2.

## Competitor snapshot persistence (task 014a2b1)
`tests/integration/test_competitor_snapshot_store.py` (20 tests) and
`tests/unit/test_market_query.py` (18 tests) pin the stored history:

- `query_hash` is the lowercase sha256 of the canonical basis JSON; the exact
  digest for a fixed basis is pinned, and every identity dimension (product type,
  route, dates, party, fare class, baggage, refundability, currency) produces a
  different query, so two products never share a cache entry;
- recording an `ok` fetch writes one row per observation with its price, currency
  and optional comparability score, and `latest` returns the payloads unchanged
  (including `source_ref` and fetch time);
- a blocked or unavailable run writes one row with no price and no currency, and
  `latest` returns `None` for it — the absence is recorded rather than hidden;
- `latest` filters by tenant and canonical query, ignores observations older than
  `max_age`, orders by site then price, and refuses a non-positive age or a naive
  clock;
- an observation for another site, an `ok` fetch carrying a blocked observation,
  or an assessment count that does not match the observations are refused;
- snapshots are append-only through the ORM (`AppendOnlyError` on update/delete)
  and through raw SQL (the PostgreSQL trigger blocks UPDATE);
- each run writes one `market.snapshot.recorded` audit entry with site, query
  hash, status and observation count (no price payload, no detail text).

## Competitor collection loop (task 014a2b2)
`tests/unit/test_market_collection.py` (24 tests) and
`tests/integration/test_competitor_collection.py` (5 tests) pin the run rules:

- a site is disabled by default; `StaticSiteGate()` contacts nothing, and
  `FeatureFlagSiteGate` maps `MakeMyTrip`/`Booking.com`/`EaseMyTrip`/`Goibibo`/
  `Agoda`/`Yatra` onto the existing `scraper_*` switches, requiring both the
  operator's environment switch and the owner's database flag (an unknown site
  cannot be turned on by a database row);
- an enabled site is fetched through the failure-isolating helper and recorded;
  a fresh stored observation satisfies a cacheable source without calling the
  adapter, and the next run reports `cached`;
- a recent `unavailable` run is `throttled` for `min_interval` and retried after
  it; a `blocked` run is never retried automatically, because an anti-bot or
  CAPTCHA block needs an operator;
- manual entry is not cacheable: it bypasses the cache and throttle, only new
  entries are stored, an all-stored batch writes nothing, and an empty manual
  source is not recorded as a failed attempt;
- observations returned by a run cover every enabled adapter's fresh rows — cached
  or just fetched — in a stable `(site, price)` order, and a disabled site's
  stored prices are excluded;
- one raising adapter is isolated (its detail names the exception type only) and
  does not stop another site;
- `CollectionPolicy` rejects non-positive durations; the loop rejects a naive
  `now`.

## Pricing rules and `NEEDS_CONFIG` (task 015a)
`tests/unit/test_pricing_rules.py` (24 tests) pins the loader without using any real
margin or tax value:

- a complete synthetic file loads, with percentages converted exactly to integer basis
  points (`8.55` → `855`), `max_age_minutes` to a `timedelta`, and the sha256
  `source_hash` stable across reads;
- a missing file is `NEEDS_CONFIG` with one `config`/`missing_file` gap and no hash; a
  missing `pricing` or `tax` section is a single section-level gap;
- each individual `null` (margin field, segment budget, GST basis, TCS reference,
  version) is reported by its exact dotted path, and the shipped
  `config/business_rules.yaml` is asserted to still be a placeholder, so filling it in
  requires a deliberate test change;
- invalid values (more than two decimals, a negative amount, unordered margins, a zero
  rounding step, a non-INR currency) raise `PricingConfigError` naming the field, and
  unknown keys inside `pricing`/`margins` are refused while unrelated top-level sections
  are ignored;
- a YAML syntax error reports a config error without echoing the file body, and a
  non-mapping root is refused.

## Pricing arithmetic and tax tables (task 015b1)
`tests/unit/test_pricing_arithmetic.py` and `tests/unit/test_pricing_tax.py` (58 tests
together with the 015a loader tests) pin the exact primitives with synthetic rates:

- FX is an exact rational plus a basis-point buffer and rounds half-up once; identity
  rates preserve the amount, conversion is monotonic, the result is within half a paise
  of the exact rational, and a currency mismatch is refused;
- nearest/up/down rounding is a multiple of the step and within one step of the input;
  `round_not_below` raises to the next step rather than crossing the floor;
- a `max` margin treats `min_paise` as a floor on the percentage, `sum` adds it, the
  target is lifted to the floor, and a floor above the cap returns `FLOOR_ABOVE_CAP`
  instead of a clamped price; generated bands stay ordered and monotonic;
- a tax line is produced only for exactly one approved row; an unapproved table, a
  missing product/basis row, or a mismatched basis is `NEEDS_CONFIG`, never zero; value
  slabs are half-open, overlapping slabs and duplicate references are refused when the
  table is built, and `not_applicable` requires an explicit zero-rated row;
- a static AST scan rejects float constants, `/` division and `float`/`round` calls in
  `src/travelos/pricing`.

## Failure-injection tests
Supplier timeout/5xx/slow; price changes mid-flow; duplicate webhooks; Redis restart; worker crash mid-booking (idempotency); WhatsApp 24h window expiry; template rejection; payment webhook before link record; clock skew; huge attachments.

## Shadow mode (task 039)
30 days or >= 100 real inquiries (whichever is longer): real inquiries are copied in by staff or via read-only channel; the system produces parsed requirements, quotes and drafts; **nothing is sent**. Staff record what they actually did. Weekly review report: accuracy, price difference, time saved, near-misses, what staff changed and why. Owner signs a go/no-go.

## Pilot (task 040)
Live mode with all actions at A1; real customers, limited scope (e.g. domestic flights + hotels, a few staff, one channel). Daily review for 2 weeks. Expand scope only after gates hold. Rollback = flip kill switches + revert to manual process (documented, rehearsed).
