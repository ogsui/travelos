# Backlog

Unrelated findings discovered while working on a task go here (one line each: what, where, why it matters). Do not fix them inside an unrelated task.

- Container image digests have not been verified on this Windows host (no Docker installed); task 037 should pin digests, run a vulnerability scan and prove `docker compose up` on CI.
- MinIO's Docker Hub repository is archived; images are moving to `quay.io/minio/minio`. Re-check the pinned tag and healthcheck before production (task 037).
- Dashboard has no ESLint/component-test setup yet; add it with the first real UI in task 017.
- Encryption key rotation/re-encryption tooling does not exist yet; the `enc:v1:` prefix reserves the format, but before the first key rotation we need an audited re-encrypt command and a key-id convention (task 002 deliberately shipped a single active key).
- Login has no rate limiting or lockout yet (task 003); add per-IP and per-account throttling with audit + alerting before shadow/live, otherwise password guessing is unbounded.
- MFA has no recovery path. An owner/admin who loses their authenticator cannot log in. Decide an owner-approved recovery flow (one-time recovery codes or a second owner reset) before pilot; do not add bypass in a hurry.
- First-time MFA enrollment is gated only by the password. A stolen password could enroll an attacker's authenticator before the real owner does. Add an out-of-band check (email/SMS to the recorded owner number, or an existing owner confirming) before the first production owner enrollment.
- `users.email` uniqueness is case-sensitive while login matches `lower(email)`; normalise on write or use a `lower(email)` unique index before user management ships (task 003 keeps emails lower-case but does not enforce it at the DB).
- `MIN_PASSWORD_LENGTH` is defined but no user-management flow enforces it yet; enforce a length/complexity policy and breached-password check when staff accounts are created.
- Outbox dead letters create human tasks but nothing alerts on them yet; add a dashboard count + alert on `task_type=outbox.dead_letter` and `status=open` (task 017 / task 037).
- Timer defaults in `workflow/timers.py` are placeholders (15 min SLA, 7-day quote expiry, etc.); owner-approved values from `config/business_rules.yaml` must override them before shadow/live.
- Approval escalation (30 min) and expiry (24 h) defaults are safety timings, not owner-agreed policy. Confirm the real values and business hours; the current metric day window is UTC, while the business timezone is Asia/Kolkata, so demotion windows may need to use the business day.
- Four-eyes monetary thresholds default to `0` (disabled) for every action. The owner/accountant must set `value_threshold_paise` per action (at minimum `quote.send`, `booking.confirm`, `booking.cancel_amend_refund`, `payment.supplier_payment`, `billing.tax_filing`) before shadow/live; do not invent amounts.
- `ads.budget_increase` is modelled as A0 (system prepares only) because the matrix says A0/A1 (owner) and hard caps are not implemented yet. Confirm whether the owner wants an A1 draft-with-approval flow, and implement the hard caps, before ads are enabled.
- `support.complaint` is modelled A1 (human leads). Confirm whether complaint replies should ever be drafted automatically or stay fully manual.
- Approval promotion is manual; the graduation tracker records the metrics but does not suggest or execute promotions. Add an owner-reviewed promotion suggestion (>=100 instances, >=95% approved unchanged, 0 incidents) in a later task.
- Approval UI is not built yet (task 017); the API returns the proposed/final payloads and the audit log has the diff, but the side-by-side screen, one-tap approve and highlighted uncertain fields need the dashboard work.
- OpenCode's documentation says free-tier chat models require the OpenCode client. The owner configured `deepseek-v4.1-flash-free`/`glm-5.3-flash-free` for server-side calls; verify a synthetic `POST /chat/completions` works with the API key before relying on it. If not, use the OpenCode client or a paid/other provider.
- LLM prices for paid models are `0` until the owner supplies a per-million-token list in integer paise (input/output, plus any cached-input or batch discount) with an effective date. Only IDs ending in `-free` are marked free, so paid models stay blocked under the ₹0 budget; set a real budget and price list before enabling them.
- The LLM daily budget is per tenant, resets at midnight in `LLM_ACCOUNTING_TIMEZONE` (Asia/Kolkata by default) and is ₹0 (free-only) by owner decision. Revisit the amount and the per-tenant split when paid models or multiple tenants are enabled.
